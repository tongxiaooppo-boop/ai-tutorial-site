第 26 天｜每天自動抓匯率

先修：第 21–22、24 天分 4 條路線，選一條走

第 26 天｜GitHub Actions 每天自動抓匯率

白話觀念卡

今天不用讓 AI 每天醒來工作。AI 幫我們寫好程式後，由 GitHub Actions 像定時開關一樣每天執行。

央行 API 不允許一般網站跨來源讀取，所以不要讓網頁直接抓央行資料。改由 Actions 下載資料，只留下最新幾筆存成 rates.json，再讓 GitHub Pages 網頁讀取自己網站裡的檔案。

這個 API 不用金鑰。未來若改用需要金鑰的服務，要放在 GitHub Secrets，不能寫進網頁、程式碼或執行紀錄。匯率只供工具練習與資料整理，不是實際換匯成交價或投資建議。

示範工具

免費主線用 AI 網頁聊天提供完整 HTML／YAML，再由學員在 GitHub 網頁建立檔案；②使用已開通的 Codex 桌面版或符合資格的 Claude Code 桌面版，③使用 VS Code 官方擴充功能。Codex Free／Go 桌面逐步開放，不能推定 IDE 同資格；Claude Code 需付費資格。④保留本地小作品。

實際每天執行的是 GitHub Actions，不需每日呼叫付費 AI API。公開 repo 的標準 GitHub-hosted runner 免費，其他情況須核對方案限制；不承諾 AI 免費修改輪數。

排程限制：排程只在預設分支執行；公開 repo 60 天沒有活動會自動停用，高負載可能延遲或丟棄工作，不能保證準點。

步驟

  1. 打開既有匯率換算器專案，先依所選路線保存版本，再請 AI 依下方提示詞提出修改計畫；不要直接授權它推送或更改帳號設定。①②③完成以下步驟；④直接看本節末尾的路線說明。
  2. 在專案建立 .github/workflows/update-rates.yml，貼入下方完整範例。它會每天 UTC 01:00，也就是台灣時間 09:00 執行，並保留手動觸發入口。排程可能延遲，不保證準點。
  3. 把網頁讀取來源改成相對路徑 ./rates.json。到 GitHub 儲存庫的 Settings → Pages，將發布來源設為 GitHub Actions。本範例會在更新資料後直接部署，避免只 commit 資料卻沒有更新網站。
  4. 將修改推送至預設分支。開啟儲存庫的 Actions，選擇此工作流程並按 Run workflow；確認下載、資料檢查、commit 與 Pages 部署成功。
  5. 檢查 GitHub 的 Actions 通知設定，讓自己接收此儲存庫的失敗郵件。暫時把 workflow 中的 API 網址改錯、推送並手動執行，確認工作流程失敗且收到郵件，再立刻還原網址並重跑。附件沒有通知設定的完整逐頁路徑：查無。
  6. 保留接下來連續兩天的自動執行紀錄，核對觸發類型是 schedule，並確認網站資料日期。假日可能沒有新匯率，因此「每天成功檢查」不等於「每天一定新增 commit」。

本日產出：連續兩天自動檢查／更新紀錄，加一次失敗通知。未完成前寫「待驗收」，不要用兩次手動執行代替。

完整 workflow

檔案位置：.github/workflows/update-rates.yml

此範例依題目提供的 API 格式編寫；本次未連線執行，不宣稱已實測此 workflow。前提是專案根目錄有可發布的 index.html，且 Pages 發布來源已改為 GitHub Actions。

name: 每日更新匯率並發布網站

on:
  schedule:
    # GitHub cron 使用 UTC；台灣 09:00 減 8 小時為 UTC 01:00
    - cron: "0 1 * * *"
  # 保留手動測試入口
  workflow_dispatch:

# 寫入資料與發布 Pages 所需的權限
permissions:
  contents: write
  pages: write
  id-token: write

# 同一時間只執行一份，避免資料提交與部署互相衝突
concurrency:
  group: daily-rates-pages
  cancel-in-progress: false

jobs:
  update-and-build:
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - name: 取得預設分支程式碼
        uses: actions/checkout@v4
        with:
          ref: ${{ github.event.repository.default_branch }}

      - name: 準備 Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: 下載並驗證央行匯率
        env:
          # 此 API 不需要金鑰，因此不需要建立 Secrets
          RATE_API_URL: https://cpx.cbc.gov.tw/api/OpenData/FTDOpenData_Day
        run: |
          python - <<'PY'
          import json
          import os
          import urllib.request
          from datetime import datetime
          from decimal import Decimal
          from pathlib import Path

          request = urllib.request.Request(
              os.environ["RATE_API_URL"],
              headers={"User-Agent": "daily-rates-learning-project"}
          )
          with urllib.request.urlopen(request, timeout=60) as response:
              data = json.load(response)

          # 不符合預期時直接失敗，不覆蓋既有的正常資料
          if not isinstance(data, list) or not data:
              raise ValueError("API 必須回傳非空陣列")

          by_date = {}
          for row in data:
              if not isinstance(row, dict):
                  raise ValueError("資料項目必須是物件")

              date = str(row["日期"]).strip()
              rate_text = str(row["NTD_USD"]).strip()

              if len(date) != 8 or not date.isdigit():
                  raise ValueError("日期必須是八位數 YYYYMMDD")
              datetime.strptime(date, "%Y%m%d")

              rate = Decimal(rate_text)
              if not rate.is_finite() or rate <= 0:
                  raise ValueError("匯率必須是有效正數")

              by_date[date] = {
                  "日期": date,
                  "NTD_USD": rate_text
              }

          # 不假設 API 的原始排序；依日期取最新七筆
          latest = [
              by_date[date]
              for date in sorted(by_date, reverse=True)[:7]
          ]

          output = json.dumps(
              latest, ensure_ascii=False, indent=2
          ) + "\n"

          # 先完成驗證，再替換正式檔案
          temporary = Path("rates.json.tmp")
          temporary.write_text(output, encoding="utf-8")
          temporary.replace("rates.json")

          print(f"檢查完成：保留 {len(latest)} 筆")
          print(f"最新資料日期：{latest[0]['日期']}")
          PY

      - name: 有資料變更才提交
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add rates.json

          if git diff --cached --quiet; then
            echo "資料沒有變更，不新增 commit"
          else
            git commit -m "更新最新匯率資料"
            git push
          fi

      - name: 準備靜態網站
        run: |
          test -f index.html
          mkdir -p _site
          # 複製網站內容，但排除 Git 紀錄、工作流程與本機環境檔
          rsync -a \
            --exclude='.git/' \
            --exclude='.github/' \
            --exclude='_site/' \
            --exclude='node_modules/' \
            --exclude='.env*' \
            ./ _site/

      - name: 設定 GitHub Pages
        uses: actions/configure-pages@v5

      - name: 上傳網站成品
        uses: actions/upload-pages-artifact@v3
        with:
          path: _site

  deploy:
    needs: update-and-build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: 發布 GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

權限與發布提醒

  • contents: write 是讓 workflow 能提交 rates.json；pages: write 與 id-token: write 用於本範例的 Pages 部署。
  • 儲存庫或組織政策、分支保護仍可能阻止推送；遇到拒絕時先看錯誤，不要直接關掉所有保護。
  • 此處沒有使用自訂金鑰。若未來服務需要金鑰，應存入儲存庫的 Settings → Secrets and variables → Actions，再由 workflow 以 ${{ secrets.金鑰名稱 }} 讀取；不要傳到前端。
  • 發布前檢查檔案內容：此範例會發布專案中的網站檔案，不能把私人文件放進專案。公開儲存庫本身也不適合保存機密。

網頁讀取方式

將原本直接抓央行 API 的部分，改成讀取同網站資料。以下是讀取與換算的核心，不是完整介面：

async function loadLatestRate() {
  const response = await fetch("./rates.json", {
    cache: "no-store"
  });

  if (!response.ok) {
    throw new Error("匯率資料讀取失敗");
  }

  const rows = await response.json();
  if (!Array.isArray(rows) || rows.length === 0) {
    throw new Error("匯率資料格式錯誤");
  }

  const latest = rows[0];
  const rate = Number(latest.NTD_USD);

  if (!Number.isFinite(rate) || rate <= 0) {
    throw new Error("匯率數值無效");
  }

  return {
    date: latest["日期"],
    rate
  };
}

// 本例 1 美元 = rate 元新台幣：
// 美元換台幣：美元金額 * rate
// 台幣換美元：台幣金額 / rate
// 畫面應顯示資料日期；讀取失敗時顯示錯誤，不要假裝是最新資料。

路線①：網頁版

  1. 打開 GitHub repo，依共用提示詞向 AI 索取完整新版 index.html 與 YAML；聊天不能直接改你電腦檔案。
  2. Add file → Create new file，輸入 .github/workflows/update-rates.yml，貼入上方完整 workflow，核對後 Commit changes 到預設分支；在網頁編輯 index.html，改成讀取同站 ./rates.json 並提交。
  3. 到 Settings → Pages 改用 GitHub Actions，Actions → Run workflow 測試；依上方共用步驟完成故意失敗、還原與兩天排程驗收。還原網址時在網頁編輯並重新 commit；需要舊內容可從 History 複製貼回。

路線②：桌面 App

  1. 桌面 App 開啟專案，先提出計畫，再在沙箱／Manual 權限內建立 .github/workflows/update-rates.yml 與修改 HTML；沿用第 2 天安全提醒，不開 Full Access／Bypass 省略檢查。
  2. GitHub Desktop 的 Changes 檢查 YAML、資料路徑與 HTML，填 Summary、Commit to 預設分支、Push origin。
  3. 在 GitHub 網頁設定 Pages 為 GitHub Actions，手動執行並完成共用驗收；故意改錯後以 Desktop 檢查、提交與推送，還原可在 History 對該錯誤 commit 用 Revert Changes in Commit，再 push。

路線③：VS Code

  1. VS Code 開啟專案，在 .github/workflows/update-rates.yml 貼入完整 workflow，修改 index.html 讀取同站資料；也可請已選定代理協助，但須檢查實際差異。
  2. Source Control 核對修改，僅暫存需要的檔案，commit 並推送至預設分支。
  3. GitHub 網頁設定 Pages 為 GitHub Actions、Run workflow；完成共用驗收。故意改錯 API 後保存失敗證據，再改回網址、檢查、commit、push 並重跑。

路線④：本地小作品

本步驟不適用：本地小作品不部署、不排程，繼續用第 5 天的下載 JSON → 匯入方式；本課到此完成，請直接到第 27 天。日後想公開與自動更新，可以回來走①，先完成第 6 天 Pages 與公開內容檢查。

驗收

以下適用①②③；④以本地 HTML 可用、能匯入 JSON 且保留版本副本驗收，不要求排程與通知。

  • 是／否：連續兩天都有 schedule 觸發且成功的紀錄，並核對 rates.json 最多七筆、由新到舊排列？
  • 是／否：Pages 網頁讀的是同站 rates.json，顯示資料日期，且 100 美元在範例匯率下得到 3,286 元新台幣？
  • 是／否：是否完成一次故意失敗、收到失敗郵件，並還原後成功重跑？

正常範例

  • 輸入：API 資料包含 {"日期":"20261111","NTD_USD":"32.86"}，使用者輸入 100 美元。
  • 預期結果：rates.json 最新一筆日期為 20261111；網站顯示資料日期及 3,286 元新台幣。若隔天來源資料未變，工作流程仍可成功，但不新增資料 commit。

失敗範例

  • 錯誤輸出：前端顯示 Failed to fetch，程式仍直接讀央行 API。
  • 怎麼看出來：瀏覽器的網路請求指向央行，而不是自己網站的 rates.json；代表尚未完成同站資料架構。
  • 另一個警訊：Actions 下載失敗，網頁卻顯示「今日最新」。舊資料可以保留，但必須顯示實際資料日期，不能宣稱已更新。

常見錯誤
  • cron 直接填台灣時間。GitHub 使用 UTC；台灣時間要減 8 小時，跨日也要一起換算。
  • 只給讀取權限，卻要求 commit。需要 contents: write，但仍須遵守儲存庫與分支政策。
  • 認為 commit 成功就一定發布成功。要另外檢查 Pages 部署；本範例已把部署納入同一流程。
  • 把金鑰藏在 HTML、公開 repo 或執行紀錄。這個 API 不需要金鑰；未來若需要，使用 Secrets，外洩仍須到發行服務撤銷重發。
  • 把沒有新匯率當失敗，或完全不驗證通知。假日可能沒有新資料；失敗郵件也受通知設定影響，必須實際測一次。
