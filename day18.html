第 18 天｜準備工具（選路線）

★ 最低完成路線先修：第 17 天分 4 條路線，選一條走

第 2 天｜準備工具：選一條路線，存下第一個版本

白話觀念卡

儲存是留下目前內容；版本紀錄則是留下可以比較、找回的存檔點。GitHub 網頁能直接提交（commit）；桌面路線先 commit 到本機，再 push 到 GitHub。本地小作品則用不同檔名保存副本。

今天只選一條路線，把昨天規格存下來。AI 只需要接觸這個練習專案，不要讓它從整個桌面、下載資料夾或整顆硬碟開始工作。

示範工具

免費主線選 Gemini 網頁版協助解釋操作，或 Claude Free 建立 Artifacts；ChatGPT 可協助討論，但現行 Free 單一 HTML 直接下載資格查無完整確證。實際存版本的工具依下方路線選擇。

Codex 桌面 Free／Go 仍逐步開放；Claude 桌面 Code 需 Pro 以上等符合資格方案。安裝免費不代表模型服務免費。

步驟

先打開瀏覽器，準備昨天的規格。①②③需要 GitHub 帳號，登入與驗證自行在官方畫面完成，不把密碼、驗證碼或復原碼貼給 AI。

路線①：網頁版

  1. 在 GitHub 網頁選 New repository，建立 fx-practice；日後用免費 Pages 需公開，現在就檢查規格沒有個資。
  2. 選 Add file → Create new file，檔名填 README.md，貼入昨天規格。
  3. 填提交訊息「建立匯率換算器規格」，Commit changes 到 main，確認檔案與提交紀錄可見。不用安裝 Git。

路線②：桌面 App

  1. 先在 GitHub 網頁建立自己的 fx-practice repo 並存入 README.md 規格；安裝免費 GitHub Desktop 並登入。
  2. 在 Desktop 選 File → Clone Repository，選該 repo、指定專用 Local Path，再 Clone。
  3. 安裝並登入 Codex 桌面版，開啟該專案資料夾；或 Claude 桌面版 Code → Local → Open folder 選同一資料夾。沒有資格就改走①。
  4. 日後在 Desktop 的 Changes 核對差異，勾選檔案、填 Summary、Commit to main，再 Push origin。今天先確認 History 看得到規格。

安全提醒：Codex 保留沙箱及最小權限；Full Access 超出專案限制，可能造成破壞或資料遺失。Auto-review 不取代沙箱，.env 也不能假定預設被阻擋。Claude 先用 Plan／Manual 並檢查修改與指令；核准的 Bash 仍可能寫到其他位置。Bypass permissions 官方只建議用於沙箱容器或 VM。Windows 避免不明 WebDAV／網路路徑，只接可信任 MCP；金鑰檔案有權限設定也不保證不外洩。

路線③：VS Code

  1. 從本課官方連結安裝 VS Code 與 Git for Windows，完成後重開 VS Code。
  2. 用檔案總管建立專用 fx-practice，在 VS Code 選 File → Open Folder；建立 README.md 並貼入規格。
  3. Terminal → New Terminal，確認位置只在這個專案，逐行執行；姓名可用暱稱，信箱換成 GitHub Settings → Emails 的 noreply 信箱：
git --version
git init -b main
git config user.name "你的暱稱"
git config user.email "換成GitHub顯示的noreply信箱"
git add README.md
git commit -m "建立匯率換算器規格"
git log -1 --oneline
git status

設定只套用目前專案。最後確認有紀錄且工作目錄乾淨；commit 還不是上傳。

路線④：本地小作品

  1. 打開檔案總管，建立專用 fx-practice 資料夾。
  2. 用純文字編輯器存下規格，另存一份 規格-v1.txt，保留正常副本。
  3. 不需要 GitHub、Git 或代理；第 4 天取得完整 HTML 後另存 fx-v1.html，之後改版存 fx-v2.html。

範例提示詞

請當我的入門操作教練，先解釋，不刪檔或更改系統設定。
<環境資料>
Windows；選擇路線：【①／②／③／④】。
專案：fx-practice；今天要保存作品規格。
我做的動作：【填實際操作】。
實際結果：【貼文字，先移除個資、秘密與私人路徑】。
</環境資料>
請輸出白話解釋、已確認與未確認的事，下一個檢查動作只給一個，
並說明成功時應看到什麼。不要要求密碼、驗證碼或權杖。

驗收

  • 是／否：規格已存下，重新打開仍看得到？
  • 是／否：能找到 GitHub 提交紀錄、Desktop History、Git log 或本地副本其中一種證據？
  • 是／否：知道目前存檔不代表網站已發布？

正常範例：輸入昨天規格並存檔，重新開啟後內容一致，能指出存檔點。

失敗範例：AI 說「已備份」，卻找不到實際檔案或紀錄；先確認儲存位置。

常見錯誤
  • 把 VS Code 與 Visual Studio 混為同一套軟體。
  • Git 裝好卻沒重新開啟終端機，誤以為安裝失敗。
  • 在桌面根目錄或整個文件資料夾執行 git init。
  • 用真實私人信箱建立公開版本紀錄，之後才發現信箱也跟著公開。
  • 把 GitHub 密碼、驗證碼或復原碼貼給 AI；登入應在官方登入畫面自行完成。
