第 21 天｜API 入門

★ 最低完成路線先修：第 20 天

第 5 天｜API 入門：讀取官方匯率，保護金鑰

白話觀念卡

API 是讓程式依約定向另一個服務索取資料的入口。程式送出請求，服務回傳資料；JSON 是常見的資料格式。呼叫 API 不一定要用 AI，也不一定需要金鑰。

今天採用中央銀行公布的美元對新臺幣銀行間收盤資料。它與台銀現金、即期買賣牌告不同，不能當成臨櫃成交價。

有些 API 需要像密碼一樣保管的金鑰。.env 可用來放本機設定，但不會自動加密，也不能讓網頁前端藏住秘密。本課公開資料不需要另外申請 AI API 金鑰。

示範工具

  • 首選：Gemini 免費版。可協助解釋少量 JSON、依實際欄位產生讀取程式；資料本身由官方 API 提供。
  • ChatGPT：同樣可解釋 API 回應與修改解析程式；ChatGPT 免費聊天不能推定為免費 AI API。
  • Claude：適合逐段解釋資料解析與錯誤處理；Claude 聊天、Claude Code、Claude API 分別核對資格與費用。

今天使用的資料

採用政府資料開放平臺第 7232 號資料集data.gov.tw所列的中央銀行日資料 APIcpx.cbc.gov.tw。官方資料集列為免費，欄位說明包含日期、NTD/USD。

台銀牌告已先查閱，但這堂課選用有明確公開 API 入口的央行資料。

備課實測（2026-11-11）：回應是一個陣列，每筆長這樣 {"日期":"20261111","NTD_USD":"32.86"}，從 2008 年起逐日累積，全檔約 190 KB；日期是 YYYYMMDD 字串、匯率是字串，要轉成數字。伺服器只允許 petstore.swagger.io 跨來源讀取，放在 GitHub Pages 的網頁用 fetch 直接抓會被瀏覽器擋（CORS），所以本課採「先下載、再匯入」；第 26 天改由 GitHub Actions 每天下載。上課時仍以學員自己下載到的實際回應為準。

步驟

  1. 打開瀏覽器讀官方資料說明。辨認資料是「銀行間收盤匯率」，理解 NTD/USD 代表每 1 美元對應的新臺幣數值。今天的成品保留美元轉新臺幣。
  2. 用 Windows PowerShell 取得 API 回應。在 VS Code 開啟 fx-practice 的終端機，執行下方指令，下載為 rates-response.json。這是程式發出的資料請求，不是在執行網頁程式。
  3. 查看實際資料，再請 AI 解釋。用 VS Code 開啟下載檔，提供頂層結構及少量完整紀錄給 AI。要求指出資料清單在哪、日期與匯率欄位在哪；若回來的是錯誤頁或空內容，先停在這一步。
  4. 修改單一 HTML，加入「選擇匯率資料檔」。讓網頁讀取剛下載的 JSON，依已確認欄位找出日期最新、匯率有效的紀錄；顯示來源、資料日期及匯率。檔案在瀏覽器本機解析，不上傳。原本固定值保留為明確標示的「練習模式」。
  5. 了解瀏覽器直接抓資料的差異。備課實測：央行 API 不允許一般網站跨來源讀取，網頁直接 fetch 會在瀏覽器主控台出現 CORS 錯誤。可以加做一個「向官方更新」按鈕親眼看這個錯誤，然後回到本課的下載後匯入路線。不要關閉瀏覽器安全功能，也不要接陌生的免費轉送服務。
  6. 做金鑰保護練習，再建立存檔點。只用下面的假金鑰建立 .env，加入 .gitignore 並驗證它未被追蹤；公開作品只使用免金鑰資料。資料模式與練習模式都測完後再 commit。

第 2 步，在專案終端機執行：

Invoke-WebRequest -Uri "https://cpx.cbc.gov.tw/api/OpenData/FTDOpenData_Day" -OutFile ".\rates-response.json"

若下載失敗，保留完整錯誤文字，依第 7 天格式詢問 AI。不要以自己編的 JSON 冒充成功回應。

第 6 步，.env 只放假值：

EXCHANGE_API_KEY=DEMO_ONLY_NOT_A_REAL_KEY

.gitignore 加入：

.env
.env.*
!.env.example

可分享的 .env.example 只留空欄位：

EXCHANGE_API_KEY=

確認忽略規則與追蹤狀態：

git check-ignore .env
git ls-files .env

預期第一個指令顯示 .env，第二個沒有輸出。

要記住的界線：如果將來改用需要秘密金鑰的服務，要由後端程式讀取環境變數並代為呼叫。GitHub Pages 沒有這種後端執行環境；不要把 .env 讀進 HTML，也不要把秘密金鑰塞進前端建置結果。

範例提示詞

請協助我把既有單一HTML匯率換算器，加入官方資料檔匯入功能。
先確認實際資料結構，再寫解析程式。

<作品現況>
檔案：index.html。
原功能：USD轉TWD，固定練習值1 USD＝32 TWD。
接下來要支援：選擇一份本機JSON檔，讀取官方匯率資料。
網頁維持單一HTML，不使用框架、不上傳檔案內容。
</作品現況>

<資料來源說明>
提供機關：中央銀行。
內容：銀行間市場新臺幣對美元收盤匯率日資料。
官方資料集說明的欄位：日期、NTD/USD。
這不是銀行現金或即期買賣牌告，也不是即時交易報價。
</資料來源說明>

<API實際回應>
【貼上剛下載JSON的頂層結構與少量完整紀錄，保留原始欄名。
尚未取得資料時，請保留這段並讓AI先指出資料不足。】
</API實際回應>

<既有程式>
【貼上目前完整index.html；程式代理則指定它讀取該檔案】
</既有程式>

請先輸出：
1. 實際JSON的資料路徑、日期欄位與匯率欄位對照表。
2. 如何判斷最新日期，不能假設第一筆或最後一筆一定最新。
3. 資料不足或格式不符時，還需要我提供什麼。

欄位能確認後，再提供完整index.html或可檢查的修改。
要求：
- 匯率必須是大於0的有限數字；缺值不能當0。
- 顯示來源、資料日期、單位與換算方向。
- 匯入失敗要說明原因，不能偷偷改用32並標成官方資料。
- 練習模式必須清楚標示。
- 不讀取.env、不要求任何金鑰、不增加換匯建議。
最後附正常、空檔、欄位缺漏、錯誤格式的測試方式。

驗收

  • 是／否：真的向官方 API 發出請求，並檢查取得的檔案內容？
  • 是／否：頁面顯示資料日期與來源，能分清官方資料模式、練習模式？
  • 是／否：.env 被忽略且未被 Git 追蹤，HTML 裡沒有秘密金鑰？

正常範例

輸入：測試用的標準化資料為「日期已確認、rate＝32、方向為 TWD／USD」，金額為 100 USD。這組 32 是測試值，不冒充 API 現值。
預期：3,200.00 TWD；使用真實官方資料時，則以同日期原始數值乘以 100，人工核對結果。

失敗範例

輸出：「今天最新台銀即時匯率：32」，但剛剛的 API 請求失敗。

辨識方式：來源、資料性質與成功狀態都不一致。程式應顯示讀取失敗，或由使用者明確切換到練習模式。

常見錯誤
  • 把央行銀行間收盤資料標成台銀現金賣出價，或拿它判斷何時換錢。
  • 看見 API 網址能在瀏覽器開啟，就以為任何網頁都能用 fetch 讀取。
  • 沒看實際資料，直接猜 JSON 欄位或把空字串轉成零。
  • 以為 .env、.gitignore、登入畫面能保護送到瀏覽器的秘密金鑰。
  • 金鑰已外洩，只刪檔案卻不撤銷；應先到服務官方撤銷或更換，歷史紀錄另行處理。
