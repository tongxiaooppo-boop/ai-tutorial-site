第 22 天｜部署到 GitHub Pages

★ 最低完成路線先修：第 21 天

第 6 天｜部署：讓別人打開你的 GitHub Pages 網站

白話觀念卡

部署是把作品放到網站服務，讓別人透過網址開啟。GitHub 儲存庫放原始檔案；GitHub Pages 把適合的檔案發布成網站。兩個網址用途不同。

GitHub Free 可從公開儲存庫發布 Pages，所以原始碼也會公開。今天發布的是單一 HTML 靜態網站：換算程式在訪客瀏覽器執行，Pages 不會替你執行 PowerShell，也不會定時更新匯率。

若使用第 5 天的匯入方式，訪客需要自己選資料檔；公開網站不會自動取得你電腦上的檔案。

示範工具

  • 首選：Gemini 免費版作為發布前檢查助手。可協助檢查 HTML 與步驟，GitHub Pages 的發布由學員自行操作。
  • ChatGPT：可協助解釋部署訊息；一般聊天沒有替你發布的能力時，不能宣稱網站已上線。
  • Claude：可協助檢查程式與錯誤；Artifacts 分享與 GitHub Pages 是不同發布方式。

步驟

  1. 打開 VS Code，檢查要公開的內容。確認 index.html 在專案最上層、已通過測試。查看 Git 追蹤檔案，移除私人資料與秘密；本課不發布 .env，也不需要發布原始回應檔。
  2. 提交預定發布版本。在 Source Control 點選檔案看差異，僅暫存確認過的檔案，填寫訊息「準備發布匯率換算器」後 commit。
  3. 發布儲存庫。從 VS Code 命令選擇區執行 Publish to GitHub，在官方畫面登入，建立名為 fx-practice 的公開儲存庫。選 Public 前再次確認內容可公開；若已有同名儲存庫，換一個練習名稱。
  4. 開啟 Pages 設定。在 GitHub 儲存庫選「Settings → Pages」，Source 選 Deploy from a branch，Branch 選 main，資料夾選 /(root)，儲存。不需要特別建立名為 gh-pages 的分支。
  5. 等部署成功後開啟網站。從 Pages 設定提供的實際網址進入，不要拿儲存庫網址當成網站網址。用無痕視窗及手機重做正常值、空白、負數與資料匯入測試。
  6. 練習更新一次。在本機修改一段頁面說明、儲存、檢查 diff、commit，再用 VS Code 的同步／推送功能傳到 GitHub。等新部署成功，重新整理確認文字已更新。

第 1 步可使用：

git status
git ls-files

發布前至少確認：沒有 .env、私人截圖、帳單、存取權杖；程式沒有讀取自己電腦絕對路徑的需求。

範例提示詞

請幫我做GitHub Pages發布前檢查，只檢查與說明，不代我發布。

<發布條件>
作品：fx-practice。
首頁：儲存庫最上層的index.html。
發布方式：main分支、根目錄。
網站是單一HTML，沒有後端與建置流程。
官方匯率採本機JSON檔匯入；使用者自行選檔。
固定練習模式必須明確標示。
不公開.env與任何秘密金鑰。
</發布條件>

<檔案清單>
【貼上git ls-files輸出】
</檔案清單>

<首頁程式>
【貼上index.html；程式代理可指定讀取該檔】
</首頁程式>

請用表格輸出：
檢查項目｜通過或待處理｜檔案與位置｜修正方法。

特別檢查：
首頁名稱、外部資源、私人路徑、秘密資訊、
練習模式標示、錯誤提醒與手機顯示。

無法從資料確認的項目寫「需實際開站測試」，
不要假裝已測試網址，也不要把儲存庫建立當成部署完成。

驗收

  • 是／否：從 Pages 提供的實際網址進入，能看到完整換算器？
  • 是／否：無痕視窗可使用，沒有依賴自己的登入狀態或本機檔案路徑？
  • 是／否：更新經過 commit、推送與部署後，網站真的出現新文字？

正常範例

輸入：從 Pages 設定開啟網站，選練習模式並輸入 100 USD。
預期：顯示 3,200.00 TWD 與練習標示；資料模式則先要求選擇有效資料檔。

失敗範例

輸出：網站只顯示 README，或出現 404。

辨識方式：先檢查發布分支、根目錄及小寫 index.html 是否一致，再查看部署狀態；不要立刻重建帳號或刪除整個儲存庫。

常見錯誤
  • 以為「已推送檔案」就代表 Pages 已部署成功。
  • 以為發布分支一定要叫 gh-pages；官方支援選定分支與發布資料夾。
  • 本機檔名大小寫混用，上線後資源找不到。
  • 以為私有儲存庫或難猜的網址，就能保護已發布的網站內容。
  • 誤把 .env 拖到 GitHub 網頁上傳；網頁手動上傳不會替你依本機 .gitignore 篩選。
