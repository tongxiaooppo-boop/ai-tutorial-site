第 22 天｜部署到 GitHub Pages

★ 最低完成路線先修：第 21 天分 4 條路線，選一條走

第 6 天｜部署：讓別人打開你的 GitHub Pages 網站

白話觀念卡

部署是把作品放到網站服務，讓別人透過網址開啟。GitHub 儲存庫放原始檔案；GitHub Pages 把適合的檔案發布成網站。兩個網址用途不同。

GitHub Free 可從公開儲存庫發布 Pages，所以原始碼也會公開。今天發布的是單一 HTML 靜態網站：換算程式在訪客瀏覽器執行，Pages 不會替你執行 PowerShell，也不會定時更新匯率。

若使用第 5 天的匯入方式，訪客需要自己選資料檔；公開網站不會自動取得你電腦上的檔案。

示範工具

  • 首選：Gemini 免費版作為發布前檢查助手。可協助檢查 HTML 與步驟，GitHub Pages 的發布由學員自行操作。
  • ChatGPT：可協助解釋部署訊息；一般聊天沒有替你發布的能力時，不能宣稱網站已上線。
  • Claude：可協助檢查程式與錯誤；Artifacts 分享與 GitHub Pages 是不同發布方式。

步驟

免費帳號開 Pages，repo 必須公開，程式碼與網站都可能被別人看到；不要放個資、私人截圖、帳單、權杖或 .env。不想公開就選④。

①②③提交檔案後，共用這個發布流程：GitHub repo → Settings → Pages → Source 選 Deploy from a branch → main → /(root) → Save。index.html 必須在發布資料夾頂層，不必另建 gh-pages 分支。等部署成功，開啟 Pages 提供的實際網址，以無痕視窗與手機測試；第 5 天資料模式仍需訪客自行匯入 JSON。

路線①：網頁版

  1. 打開 GitHub repo，確認根目錄 index.html 是驗收過的版本，檢查所有檔案能公開。
  2. 依共用流程開啟 Pages，區分網站網址與 repo 網址。
  3. 在 GitHub 網頁編輯一段頁面說明、核對並 commit；等新部署成功，重整檢查更新。

路線②：桌面 App

  1. 在 GitHub Desktop 檢查 Changes 與 History，確認只含可公開檔案；必要時 commit，再 Push origin。
  2. 到 GitHub 網頁依共用流程開 Pages。
  3. 在桌面 App 改一段說明、驗收，Desktop 檢查 diff、commit、push；等部署成功，再看網站文字。

路線③：VS Code

  1. 在 VS Code 執行 git status、git ls-files，檢查追蹤內容與差異，僅提交可公開檔案。
  2. 用命令選擇區 Publish to GitHub，於官方畫面登入，發布公開 fx-practice repo；已存在則推送到自己的 repo，避免重建。
  3. 到 GitHub 依共用流程開 Pages；本機改一段說明後檢查 diff、commit，再用同步／推送更新，等部署成功確認。

路線④：本地小作品

本步驟不適用：本地作品不部署，雙擊 HTML 並通過測試，本週作品到此完成；請直接到第 7 天練習除錯。日後想公開，可回來走①，把驗收過的 HTML 存為 repo 根目錄 index.html；先確認內容能公開。

範例提示詞

請幫我做GitHub Pages發布前檢查，只檢查與說明，不代我發布。

<發布條件>
作品：fx-practice。
首頁：儲存庫最上層的index.html。
發布方式：main分支、根目錄。
網站是單一HTML，沒有後端與建置流程。
官方匯率採本機JSON檔匯入；使用者自行選檔。
固定練習模式必須明確標示。
不公開.env與任何秘密金鑰。
</發布條件>

<檔案清單>
【貼上要公開的檔案清單；③也可用git ls-files】
</檔案清單>

<首頁程式>
【貼上index.html；程式代理可指定讀取該檔】
</首頁程式>

請用表格輸出：
檢查項目｜通過或待處理｜檔案與位置｜修正方法。

特別檢查：
首頁名稱、外部資源、私人路徑、秘密資訊、
練習模式標示、錯誤提醒與手機顯示。

無法從資料確認的項目寫「需實際開站測試」，
不要假裝已測試網址，也不要把儲存庫建立當成部署完成。

驗收

  • 是／否：①②③能從 Pages 網址看到完整換算器；④雙擊本地 HTML 能用？
  • 是／否：①②③無痕視窗可用；④斷網仍可使用固定練習模式？
  • 是／否：①②③更新部署後真的出現新文字；④新版副本有新文字且舊版保留？

正常範例

輸入：從 Pages 設定開啟網站，選練習模式並輸入 100 USD。
預期：顯示 3,200.00 TWD 與練習標示；資料模式則先要求選擇有效資料檔。

失敗範例

輸出：網站只顯示 README，或出現 404。

辨識方式：先檢查發布分支、根目錄及小寫 index.html 是否一致，再查看部署狀態；不要立刻重建帳號或刪除整個儲存庫。

常見錯誤
  • 以為「已推送檔案」就代表 Pages 已部署成功。
  • 以為發布分支一定要叫 gh-pages；官方支援選定分支與發布資料夾。
  • 本機檔名大小寫混用，上線後資源找不到。
  • 以為私有儲存庫或難猜的網址，就能保護已發布的網站內容。
  • 誤把 .env 拖到 GitHub 網頁上傳；網頁手動上傳不會替你依本機 .gitignore 篩選。
