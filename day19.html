第 19 天｜程式代理

★ 最低完成路線先修：第 18 天

第 3 天｜程式代理：安裝 Codex、Claude Code，完成第一次修改

白話觀念卡

聊天型 AI 通常把程式給你，再由你貼入檔案。程式代理則能在授權範圍內讀取專案、修改檔案、執行指令。方便的同時，也必須知道它開了哪個資料夾、取得哪些權限、改了什麼。

擴充功能可以免費安裝，但服務可能需要付費資格。Codex 官方目前將 Free 的使用範圍列為逐步開放的桌面 App；不能保證免費帳號能用 VS Code 擴充功能。Claude Code 也不能直接用 Claude Free 聊天資格代替。

示範工具

  • 免費主線：Gemini 免費版。協助寫出第一次修改內容，由學員自行貼入 VS Code，可繼續完成全週作品。
  • ChatGPT／Codex：今天認識 Codex 官方擴充功能；使用 IDE 需核對方案與帳號權限，Free 桌面資格不等於 IDE 資格。
  • Claude／Claude Code：官方擴充功能支援符合資格的付費 Claude 訂閱或 Console 帳號；Console 使用可能產生 API 費用。

課堂安排：有符合資格帳號的學員實作代理；其餘學員觀看老師示範，再走免費主線。今天不必為了繼續課程輸入信用卡。

步驟

  1. 打開 VS Code 的 fx-practice。先執行 git status，確認昨天的規格已儲存成 commit。
  2. 安裝 Codex。按 Ctrl＋Shift＋X 開啟 Extensions，搜尋 Codex，核對發行者為 OpenAI、識別碼為 openai.chatgpt。安裝後點 Codex 圖示；找不到時用命令選擇區搜尋 Codex: Open Codex Sidebar。
  3. 完成 Codex 登入與資格檢查。依官方登入流程操作。若顯示方案不支援，記下訊息並走免費主線。Windows 依目前官方流程設定沙盒，不因舊文章而先安裝 WSL。
  4. 認識 Claude Code 的安裝。在 Extensions 搜尋 Claude Code，核對發行者 Anthropic、識別碼 anthropic.claude-code。安裝後開啟面板、點 Sign in，在瀏覽器完成授權。擴充功能已包含面板所需 CLI，不必先額外安裝終端機版。
  5. 只選一個入口做第一次修改。代理先用唯讀／Plan 了解專案；Claude Code 修改練習可選 Manual，逐次檢查提議。請它只在 README.md 加一行「版本：第 3 天練習」。免費主線則請 Gemini 產生那一行，自己貼入。
  6. 核對結果並存檔。查看 git diff -- README.md，確認只有預期文字變動，再提交這次修改。
git diff -- README.md
git add README.md
git commit -m "加入課堂版本標示"

不要同時讓兩個代理修改同一份檔案。

範例提示詞

請協助我完成第一次小修改，先確認範圍，再處理。

<專案資料>
目前專案：fx-practice。
目標檔案：README.md。
需求：在文件最後新增一行「版本：第3天練習」。
其他內容不需要調整。
這是入門練習，不需要套件、網路連線或系統設定變更。
</專案資料>

請先回答：
1. 你要讀取哪個檔案？
2. 預計修改哪個位置？
3. 我要怎麼確認只有這項修改？

若你具有本機修改能力，依目前權限模式提出或完成這項修改，
最後列出實際修改檔案與檢查方式。
若你只是聊天工具，請直接提供我要貼上的那一行，
不要說已經修改我的電腦檔案。

驗收

  • 是／否：安裝前有核對官方發行者與擴充功能識別碼？
  • 是／否：知道自己的帳號是否有 IDE 代理使用資格？
  • 是／否：實際 diff 只有指定的版本標示？

正常範例

輸入：要求在 README.md 最後加入版本標示。
預期：只有這份檔案增加一行；聊天工具則只提供文字，沒有宣稱已修改本機。

失敗範例

輸出：「環境已最佳化」，同時新增多個設定檔、修改系統設定。

辨識方式：這些變更與指定的一行文字無關。停止後續操作，逐檔檢查，不要整批接受。

常見錯誤
  • 以為裝好擴充功能就取得免費模型額度。
  • 把 VS Code 內建代理選單與另外安裝的官方擴充功能混在一起。
  • 以為代理每個動作都會詢問；自動模式可能直接修改工作區檔案。
  • 為了省事選擇完整存取、Bypass，卻不知道開放了哪些範圍。
  • 把專案中的秘密檔案開在編輯器，誤以為 .gitignore 也會禁止 AI 讀取。
